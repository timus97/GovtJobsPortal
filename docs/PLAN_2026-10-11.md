# Plan — 11 October 2026

Read-only review of the Java host. Two reviewers walked the repo: a QA lead and a product owner. This file is their merged plan. No code, tests, server, or database were changed, and none were run.

Branch `phase-a-one-catalog` at `f960ace`, plus the uncommitted collector cutover (React client, Express server, and the Pages workflow are deleted in the working tree). The host on disk is Java 21, Spring Boot 4.1.1, and Thymeleaf. Students read the catalog from Postgres. Git JSON is the collector inbox.

Postgres was not queried. If a process on port 8090 was started from an older jar, the screen can differ from this tree. Start the next look with `.\scripts\java21.ps1` then `.\scripts\start-web.ps1`.

This plan does not replace `docs/FIX_PRIORITY.md`. It says which open items to do, which to leave, and in what order.

## Product snapshot

Sarkari Desk is a private desk for an Indian job candidate, plus a separate operator console. It is not a government site and it does not apply for anyone. A candidate saves a few facts, compares them with notices an operator has approved, keeps their own list, and stores admit and result files on this host. An operator pastes an official `https://` link or runs the Java collector so that list can change.

| Surface | Routes | Who can finish what today |
| --- | --- | --- |
| Jobs | `/jobs`, `/jobs/{id}` | Anyone can filter approved notices and open an `https://` official link. Track is a real save only after sign-in, and the button does not say that. |
| Prepare | `/prepare` | Anyone can scan named calendars and open an official link. A prose date stays as written. An empty calendar says no date is on file. Track is a real save only after sign-in. |
| Match | `/match`, `/profile` | A signed-in student with date of birth, education, and reservation category gets a ranked list and a “Did not match” list. The screen never says “you are eligible.” Age is unknown on the committed catalog. |
| Desk | `/dashboard`, `/desk/{id}` | A signed-in student can track a notice, add a custom exam, change status, and upload an admit or result. Labels and empty states still mislead. |
| Ops | `/ops`, `/ops/runs/{id}`, `/ops/fetch`, `/ops/pipeline` | Publish locally puts a pasted row on Search. Approving a crawl notice does not. The nav calls that second queue “Review.” |

**Done enough to keep designing** means a person can finish these four journeys without being misled:

- A visitor can tell sample cards from real notices, see which windows are still open today, and understand a missing official button.
- A student can register, save a profile, read a match as pass, fail, closed, or unknown, and land that notice on the desk with a clear confirmation.
- The desk can carry Watching through a private admit file and a private result file, in plain language, with no study-plan sentence.
- An operator can see which action changes Search, and after Publish locally can open the student card and see which facts were never collected.

## What is already solid

Leave these alone.

- The product never prints “you are eligible.” Landing, the student disclaimer, and Match say the official notice decides.
- Age relaxation is only a number printed on the notice for that category. There is no default OBC, SC, or ST bump. Collectors do not write `ageRelaxation`.
- Reservation category is required before a match runs. The profile offers UR, EWS, OBC, SC, and ST.
- Unknown age and unknown education do not fail a row. Free-text `eligibility[]` is not parsed.
- Official buttons on jobs, match, prepare, and desk require `https://`. Paste and the priority crawl use `OfficialUrlPolicy`. The priority fetcher does not follow redirects. The daily client follows at most three same-site redirects and refuses a bot-manager page.
- Student and operator cookies are separate, HMAC-SHA256, HttpOnly, SameSite Lax. A student password change increments `session_epoch`. Passwords are scrypt. Reset tokens are stored as SHA-256. The forgot response does not say whether the email exists. The one-time reset URL is shown only on loopback when no mailer is set and `COOKIE_SECURE` is false, and it is not logged.
- Login, register, forgot, reset, and ops login are rate-limited. `X-Forwarded-For` is not trusted.
- Request logs record method, path, status, and a student id. They do not record the query string or the email. `/health` has no profile or desk payload.
- File download checks the owner row and a fixed relative path. Custom desk URLs that are not `https://` are rejected and the message stays on the desk.
- Search hides closed rows by default. Publish locally refuses a blank or unparseable last date.
- Postgres is the student system of record. Flyway owns the schema. Sample rows hide once a real approved row exists.
- The priority crawl cannot publish. Plan and mock routes still answer and the desk does not link to them.
- The daily workflow in this working tree is the Java job. The Pages workflow is deleted here. A scrape is not stamped `qualification=graduate`.

### Slice 2 — Match: unknown is not a pass, and closed is not a personal fail

**User.** A student who wants to know what was checked against their facts.

**Depends on.** Slice 1 for the shared meaning of open, closing soon, and closed. The scoring change itself does not wait on the Search copy.

**Done when.** The ESIC row stays on the ranked list, age and education stay unknown, and domicile, gender, discipline, and category are unknown too. The score is not 75. The page shows the verify badge. A past notice is under Closed, not under “Did not match.” Copy never contains “you are eligible.”

This is the trust bug. `EligibilityMatch.matchOne` always scores eight rules. For a Postgres catalog row, age and education become unknown, which is right. These become passes when the field is simply absent (`EligibilityFacts.extractOpportunityFacts`, `EligibilityMatch.evaluateDiscipline`, `evaluateDomicile`, `evaluateGender`, `evaluateCategory`):

- No discipline field: “No discipline requirement.”
- `domicileRequired` missing is stored as false, then “No domicile restriction.”
- No gender field: “No gender restriction.”
- No `openToCategories` and not `reservedOnly`: “No reserved-only restriction listed.”

Coverage is non-unknown divided by 8. The verify badge appears only when there is no fail and confidence is under 0.6. A row with a last date and nothing else is 6/8 = 0.75, score 75, and `lowConfidence` is false. `CatalogStore.approvedJobs` does not load age, relaxation, discipline, gender, domicile, PwBD, or category. The ESIC row is that case, and its location is stored as “All India” while the title names Lucknow. PwBD is a separate pass when the student declared no disability. That one stays a pass. It is a fact about the student.

`eligibilityParse.complete` is computed and then ignored by the scorers. The published Postgres row does not store that flag.

## Open decisions

These are the only choices this plan does not settle. The recommendation is what the slices above assume. A different answer changes that slice and nothing else.

**DEC-1. Should a missing notice rule count as a pass?** Today it does, and the score treats it as a covered fact. Recommendation: no. Absence is unknown, it does not fail the row, and it lowers confidence. An explicit “no restriction” on a curated row still passes. Slice 2 assumes this. If the answer is to keep the number, drop IMP-010 and IMP-012 and keep only the wording and the Closed group.

**DEC-2. Should Sign out end every copy of the session?** Today it clears the browser cookie only. A copied cookie works until the password changes. Recommendation: yes, bump the student epoch on logout, and give operators an epoch too, because the desk stores admit files. Slice 7 IMP-063 assumes this.

**DEC-3. May registration say that an email is already in use?** That confirms the address is registered. Recommendation: no. Say the account could not be created, and point at Sign in. Slice 7 IMP-061 assumes this.

**DEC-4. Should birth state count as domicile?** `evaluateDomicile` adds `birthState` to the states that can pass a domicile rule. The form does not say so. Recommendation: leave the rule until you answer. Do not change it inside slice 2.

**DEC-5. Should an approved crawl notice ever become a student row?** Today only paste-publish and a registry rebuild change Search. Approve sets `catalog_id` null on purpose. Recommendation: leave it that way until paste publish is honest. Do not connect them in this plan.

**DEC-6. Which catalog should the next design pass use?** The committed file, once synced, has one closing-soon window on 11 October 2026. An empty database shows the sample banner. This review did not query Postgres. Recommendation: design against the synced file, and keep the sample banner for an empty database. Do not run a live crawl to fill the list as part of this plan.
